Dynamic DNS

DNS records for your own domains

This documentation describes the modified fork. Reserved example.com and *.example names below are placeholders; configure your own service domains. The original public addr.tools services are operated independently.

HOW IT WORKS

A generated secret controls the DNS name formed from its SHA-224 hash. Point a CNAME from your own subdomain at that generated name. Keep the secret private: anyone with it can change or remove the addresses.

CREATE A SECRET

Use 32 cryptographically random bytes encoded as unpadded base64url (43 characters). The API requires this exact token format and rejects query-string credentials. Generate the token cryptographically: a format check cannot prove randomness. These commands create private files without printing the secret:

umask 077 openssl rand -base64 32 | tr '+/' '-_' | tr -d '=\n' > secret.token { printf 'Authorization: Bearer '; cat secret.token; printf '\n'; } > auth.header sha224=$(openssl dgst -sha224 -r secret.token | cut -d ' ' -f 1)

Keep secret.token and auth.header outside a web root and restrict access to the updater account. A public hash lets anyone test password guesses offline, which is why randomness matters. Changing the secret changes the DNS name and requires updating your delegation.

UPDATE API

Send POST or PUT with Authorization: Bearer SECRET and an ip body field. Bodies may be URL-encoded forms or JSON. Credentials in URLs are rejected. Successful updates return HTTP 200 and OK.

curl --fail-with-body --header @auth.header --data-urlencode "ip=192.0.2.1" https://dyn.example.com/

Use ip=self for the request source IP. An operator can configure IPv4-only and IPv6-only hostnames. Each address family must be refreshed at least once every 90 days.

A GET with the bearer header and no mutation fields returns the derived domain without changing state. A DELETE with the bearer header removes both address families and returns HTTP 204. GET requests containing mutation fields are rejected.

DELEGATION EXAMPLE

printf "%s.dyn.example.com\n" "$sha224"

Use the printed name as the CNAME target of home.example.com. Refresh its address using an updater capable of HTTPS POST and bearer headers:

curl --fail-with-body --header @auth.header --data-urlencode "ip=self" https://ipv4.dyn.example.com/

Legacy clients that support only a credential-bearing GET URL are incompatible with this hardened API. Use a compatible updater or a fixed local helper; do not re-enable URL credentials to fit a client.

DATA HANDLING

Published IP records are public DNS data. The service and reverse proxy process update source addresses and may log requests. Operators must publish their actual logging and retention policy. Never include the bearer credential in logs or a support report.
