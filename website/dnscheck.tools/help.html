dnscheck.tools

ABOUT

dnscheck.tools is a tool to test for DNS leaks, DNSSEC validation, and more.

USAGE

Open this configured diagnostic service and choose Run DNS checks to observe DNS resolvers and check DNSSEC validation.

DNS TEST QUERIES

At its core, dnscheck.tools is a custom DNS test server. Make test queries like:

$ dig txt [OPTIONS.]ZONE.dnscheck.tools

  • ZONE sets the DNSSEC signing algorithm and network availability:
    • test same as test-alg13 (default may change)
    • test-alg13 sign the zone using ECDSA P-256 with SHA-256
    • test-alg14 sign the zone using ECDSA P-384 with SHA-384
    • test-alg15 sign the zone using Ed25519
    • test-alg18 sign the zone using ML-DSA-44
    • test[-...]-ipv{4,6} as above but with only IPv4 or IPv6 authoritative nameservers

OPTIONS is a hyphen-separated list containing:

  • any of:
    • random a public correlation identifier, up to 32 hex digits, useful for cache busting, identifies requests to /watch; watcher IDs must be 32 hex digits
    • compress force the use of DNS message compression in the response
    • [no]truncate request truncation behavior for UDP; server safety limits still apply
  • up to one of:
    • badsig provide an invalid DNSSEC signature in the response
    • expiredsig[t] provide an expired DNSSEC signature in the response, t seconds in the past (default 1 day)
    • nosig do not provide any DNSSEC signature in the response
  • up to one of:
    • nullip provide only the all-zero IP in A and AAAA responses
    • nxdomain respond as if the domain does not exist
    • refused refuse the query
    • txtfilln add n bytes, up to 4096, of data to TXT responses

WHAT THE RESULTS CAN ESTABLISH

REACHED means an HTTP response was received for a deliberately invalid DNSSEC test domain, including an HTTP error response. UNKNOWN means no response was available: a browser cannot distinguish DNSSEC rejection from other DNS, TLS, filtering, CORS, or network failures. NO CTRL means the valid control was unavailable. An unavailable invalid domain is not a confirmed PASS.

Resolvers can recognize test names and treat them specially. These observations cannot certify all DNS responses, prove that a VPN has no leaks, or establish a physical route. A public query ID associates traffic with a watcher, but anyone who sees it can send matching queries. RDAP labels describe registration data; ECS is a claim in the received packet.

IPv6 and encrypted-authoritative-transport labels describe observed requests. Missing observations do not prove that every resolver lacks a capability. Optional request timing includes browser and transport effects and is not pure DNS latency.

THIRD-PARTY DATA

IP addresses are grouped by their network registrants as discovered by the Registration Data Access Protocol.

Hostnames (pointer records) and authoritative nameservers are discovered by reverse DNS resolution.

The original service uses GeoLite Data created by MaxMind. This fork performs geolocation only if its operator configures a provider; location estimates do not establish the physical route taken by your traffic.

PRIVACY POLICY

The checks process your source IP address, DNS query names, public correlation ID, resolver addresses, and any advertised client subnet. The operator’s DNS and web servers can log these requests; retention and access depend on the deployment. This source does not promise that an operator collects no data.

Registration-data enrichment sends observed addresses directly from your browser to IANA bootstrap and relevant RDAP providers. Configured IP, reverse-DNS, and geolocation services receive their respective lookups. Local fonts are used. The optional WebRTC check contacts only the configured STUN servers after a separate click; it does not request microphone or camera access. No Google STUN fallback is used.

Test state remains in browser memory. The diagnostic code does not use cookies or local storage, but an operator’s proxy or third-party service may have its own policy. The operator should publish its actual logging, retention, and service providers before deployment.
