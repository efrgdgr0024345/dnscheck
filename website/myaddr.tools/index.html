Registered dynamic DNS

Names with generated owner keys

This documentation describes the modified fork. Reserved example.com and *.example names below are placeholders; configure your own service domains. The original public addr.tools services are operated independently.

GET STARTED

On a configured deployment, claim an available name and save its generated secret key. The key grants control of that registration. It cannot be recovered from this service if lost.

The original service uses Brian Shea’s myaddr.tools, myaddr.dev, and myaddr.io domains. This fork does not provide or control those domains. Available suffixes and hostnames are set by the operator.

AUTHENTICATION

Send the generated key as Authorization: Bearer KEY. Never place it in a URL. Keep an authorization header file readable only by your updater account, outside a web root, and avoid exposing it in command history or logs.

UPDATE API

On this deployment, the update route is /update. Send POST or PUT with an application/json or application/x-www-form-urlencoded body. GET does not make changes. Successful updates return HTTP 200 and OK; invalid requests return a 4xx error.

Set ip to an IPv4/IPv6 address, or self to use the update request’s source address. Setting one family replaces that family’s existing address. The operator can configure IPv4-only and IPv6-only update hosts.

curl --fail-with-body --header @auth.header --data-urlencode "ip=self" https://myaddr.example.com/update

To add a temporary ACME DNS-01 TXT record, send acme_challenge in the body instead. Challenges are served under the registration’s _acme-challenge names and expire automatically.

A DELETE /update request with the bearer header and no challenge field removes both IP address families. Include an acme_challenge body field instead to remove that one challenge. Successful deletions return HTTP 204. At most 8 distinct challenges can be active per registration; repeated additions refresh the existing value, and challenges expire after 120 seconds.

REGISTRATION API

POST /reg accepts {"name":"your-name","challenge":"TURNSTILE_TOKEN"} and returns the generated name/key pair on success. The claim page performs this step.

GET /reg with the bearer header reads registration information. DELETE /reg with the bearer header deletes the registration and releases its name. Suspended or revoked keys cannot perform ordinary updates.

EXPIRATION

Make the first update within one hour of claiming. Refresh each IP family within 90 days to keep that address active. A registration expires after 120 days without an update. Check the operator’s published policy if these defaults have been changed.

PRIVACY AND THIRD PARTIES

The service processes your chosen name, source IP address, update records and verification response. Application and proxy logging can retain names, query records and source addresses; the operator must state the actual logging and retention policy.

The claim page loads Cloudflare Turnstile after you choose to continue. That provider receives browser/network information and its script runs on the page that displays your new key. The claim page also retrieves a pinned Bootstrap stylesheet from jsDelivr. Do not claim that this deployment collects no data.

Public DNS records are public. Protect the secret key and send it only to the HTTPS endpoint of the operator you intend to trust. Report service problems to that operator; the original author is not responsible for this fork’s changes or deployment.
